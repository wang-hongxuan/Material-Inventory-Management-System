# 物资库存管理系统数据库设计说明

## 1. 数据库概况

- 数据库类型：MySQL 8.0
- 默认数据库名：`inventory_db`
- 持久化框架：Spring Data JPA
- 建表方式：SpringBoot 启动时通过 JPA 自动创建或更新表结构，完整数据库脚本位于 `docs/数据库脚本.sql`

系统主要围绕“物资档案、入库记录、出库记录、系统用户”四类数据设计。

## 2. 数据表关系

```text
users 1 ---- N inbound_records
users 1 ---- N outbound_records

materials 1 ---- N inbound_records
materials 1 ---- N outbound_records
```

说明：

- `materials` 保存物资基础信息和当前库存。
- `inbound_records` 保存入库流水，每条入库记录关联一个物资。
- `outbound_records` 保存出库流水，每条出库记录关联一个物资。
- `users` 保存系统登录用户，出入库记录保存经办人和创建人。

## 3. users 用户表

表名：`users`

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键，自增 | 用户 ID |
| username | VARCHAR(60) | 非空，唯一 | 登录账号 |
| password_hash | VARCHAR(120) | 非空 | BCrypt 加密后的密码 |
| name | VARCHAR(60) | 非空 | 用户姓名 |
| role | VARCHAR(20) | 非空 | 用户角色，`admin` 或 `operator` |
| status | INT | 非空 | 账号状态，1 启用，0 停用 |
| created_at | DATETIME | 非空 | 创建时间 |
| updated_at | DATETIME | 非空 | 更新时间 |

设计说明：

- `username` 设置唯一约束，避免重复账号。
- 密码不明文保存，只保存 BCrypt 哈希值。
- 管理员功能通过 `role=admin` 控制。

## 4. materials 物资表

表名：`materials`

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键，自增 | 物资 ID |
| code | VARCHAR(80) | 非空，唯一 | 物资唯一编号 |
| name | VARCHAR(120) | 非空 | 物资名称 |
| category | VARCHAR(80) | 非空 | 物资分类 |
| spec | VARCHAR(160) | 可空 | 规格型号 |
| unit | VARCHAR(20) | 非空 | 单位 |
| supplier | VARCHAR(120) | 可空 | 供应商 |
| location | VARCHAR(120) | 可空 | 库位 |
| safety_stock | DOUBLE | 非空 | 安全库存 |
| stock | DOUBLE | 非空 | 当前库存 |
| photo_url | VARCHAR(255) | 可空 | 物资照片路径 |
| remark | VARCHAR(500) | 可空 | 备注 |
| created_at | DATETIME | 非空 | 创建时间 |
| updated_at | DATETIME | 非空 | 更新时间 |

设计说明：

- `code` 是每种物资的唯一标识。
- `stock` 当前库存不通过编辑物资直接修改，而是由入库、出库业务自动计算。
- `safety_stock` 用于低库存预警。
- `photo_url` 保存上传后的图片访问路径，图片文件保存在后端 `uploads` 目录。

## 5. inbound_records 入库记录表

表名：`inbound_records`

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键，自增 | 入库记录 ID |
| material_id | BIGINT | 外键，非空 | 关联物资 ID |
| quantity | DOUBLE | 非空 | 入库数量 |
| unit_price | DOUBLE | 非空 | 单价，默认为 0 |
| source | VARCHAR(120) | 可空 | 来源、仓库或供应商 |
| operator | VARCHAR(60) | 非空 | 经办人 |
| remark | VARCHAR(500) | 可空 | 备注 |
| created_by | BIGINT | 外键，可空 | 创建用户 ID |
| created_at | DATETIME | 非空 | 入库时间 |

设计说明：

- 新增入库记录时，后端会在同一事务中增加 `materials.stock`。
- 删除入库记录时，会回滚库存；如果回滚后库存会变成负数，则后端拦截。

## 6. outbound_records 出库记录表

表名：`outbound_records`

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT | 主键，自增 | 出库记录 ID |
| material_id | BIGINT | 外键，非空 | 关联物资 ID |
| quantity | DOUBLE | 非空 | 出库数量 |
| recipient | VARCHAR(120) | 非空 | 领用人或领用部门 |
| purpose | VARCHAR(160) | 可空 | 出库用途或仓库 |
| operator | VARCHAR(60) | 非空 | 经办人 |
| remark | VARCHAR(500) | 可空 | 备注 |
| status | VARCHAR(20) | 可空 | 审批状态：pending、approved、rejected |
| approval_remark | VARCHAR(500) | 可空 | 审批备注或驳回原因 |
| created_by | BIGINT | 外键，可空 | 创建用户 ID |
| approved_by | BIGINT | 外键，可空 | 审批用户 ID |
| created_at | DATETIME | 非空 | 出库时间 |
| approved_at | DATETIME | 可空 | 审批时间 |

设计说明：

- 管理员登记出库后，记录状态为 `approved`，系统立即扣减 `materials.stock`。
- 操作员提交出库申请后，记录状态为 `pending`，库存保持不变。
- 管理员审批通过后，状态变为 `approved`，后端再次校验库存并扣减 `materials.stock`。
- 管理员审批驳回后，状态变为 `rejected`，库存保持不变。
- 删除已通过记录时，会把对应数量加回物资库存；删除待审批或已驳回记录时库存不变。

## 7. 库存计算逻辑

入库：

```text
物资当前库存 = 原库存 + 入库数量
```

出库：

```text
管理员提交出库：如果 出库数量 > 当前库存，则拒绝出库；否则保存为已通过，并扣减库存
操作员提交申请：如果 出库数量 > 当前库存，则拒绝申请；否则保存为待审批，库存不变
管理员审批通过：如果 出库数量 > 当前库存，则拒绝审批；否则 物资当前库存 = 原库存 - 出库数量
管理员审批驳回：库存不变
```

并发控制：

- 后端在库存变更前使用数据库悲观写锁读取物资记录。
- 对应代码位置：`MaterialRepository.findByIdForUpdate`
- 作用：避免多人同时出入库时造成库存计算错误。

## 8. 数据完整性设计

- 用户账号 `username` 唯一。
- 物资编号 `code` 唯一。
- 出入库记录关联物资，避免流水记录失去对应物资。
- 有出入库记录的物资禁止直接删除。
- 入库数量必须大于 0。
- 出库数量必须大于 0，并且提交和审批时都不能大于当前库存。
- 出库申请只有待审批状态可以执行通过或驳回操作。
